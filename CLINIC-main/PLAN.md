# خارطة الطريق (Roadmap)

هذا المستند يوضح المراحل القادمة لبناء نظام إدارة العيادة الكامل، بعد إنجاز واجهة الموقع
العامة ونظام حجز المواعيد في هذه المرحلة الأولى.

## المرحلة 1 — الواجهة العامة ونظام الحجز (تم ✅)

- الصفحة الرئيسية: نبذة عن الطبيب، الخدمات، لماذا تختارين عيادتنا، مواعيد العمل،
  التواصل والموقع، الأسئلة الشائعة، بالإضافة إلى تذييل الصفحة. جميع بيانات التواصل
  والمؤهلات والعناوين معروضة كحقول قابلة للتعديل لاحقًا من لوحة التحكم، دون افتراض
  أي معلومات لم تُقدَّم.
- تصميم عربي بالكامل مع دعم اتجاه الكتابة من اليمين لليسار (RTL)، وبنية جاهزة لإضافة
  الإنجليزية لاحقًا (كل النصوص مركزة في `src/data/clinic.ts` بدل تشتتها بالكود).
- تدفق حجز موعد كامل (`/booking`): اختيار التاريخ والوقت، إدخال بيانات المريضة، مراجعة
  الملخص وسياسة المواعيد مع رمز تحقق (CAPTCHA) بسيط، ثم شاشة تأكيد برقم حجز فريد.
- بيانات الأوقات المتاحة حاليًا مبنية على بيانات تجريبية ثابتة (`src/data/booking.ts`)
  وليست متصلة بقاعدة بيانات فعلية بعد — وهذا ما تغطيه المرحلة التالية.

## المرحلة 2 — قاعدة البيانات ونماذج الأساس

- تصميم نماذج قاعدة البيانات (Netlify DB / Postgres عبر Drizzle): المرضى، المواعيد،
  الزيارات، المتابعات، المستخدمين الإداريين، سجل التدقيق (audit log).
- ربط نظام الحجز الحالي بقاعدة البيانات الفعلية بدلاً من البيانات التجريبية: حفظ كل
  طلب حجز، وتحديث الأوقات المتاحة ديناميكيًا بدلاً من القيم الثابتة.
- إنشاء دوال خادم (server functions / API routes) لإنشاء وقراءة وتحديث المواعيد.

## المرحلة 3 — المصادقة والصلاحيات

- تسجيل دخول آمن للوحة التحكم (Netlify Identity أو نظام مصادقة مخصص) مع تفعيل الأدوار:
  مدير عام (Super Admin)، طبيب (Doctor)، موظف استقبال (Receptionist).
- نظام صلاحيات قابل للتخصيص لاحقًا يحدد من يمكنه الوصول إلى السجلات الطبية الحساسة.
- مصادقة آمنة لبوابة المريضة (تسجيل دخول برمز OTP عبر الهاتف/البريد) لعرض مواعيدها
  ومتابعاتها فقط دون أي بيانات طبية حساسة غير مصرح بها.
- سجل تدقيق (audit log) لكل عملية وصول أو تعديل على بيانات المريضات.

## المرحلة 4 — لوحة تحكم الإدارة

- شاشة إحصائيات يومية (مواعيد اليوم، تأكيد، معلّق، مكتمل، ملغى، لم يحضر، مريضات جديدات،
  متابعات مستحقة) بأرقام حقيقية من قاعدة البيانات، مع رسوم بيانية بسيطة.
- صفحة إدارة المواعيد بعروض يومية/أسبوعية/شهرية/تقويمية، مع إجراءات: إنشاء، تعديل،
  تأجيل، تأكيد، إلغاء، إتمام، تسجيل "لم يحضر"، إضافة ملاحظات، إنشاء موعد متابعة.
- فلاتر بحث بالتاريخ، الحالة، نوع الزيارة، واسم المريضة.

## المرحلة 5 — إدارة المرضى والسجل الطبي

- قاعدة بيانات كاملة للمرضى: إضافة، تعديل، بحث، عرض ملف المريضة (بيانات أساسية، تاريخ
  المواعيد، تاريخ الزيارات، تاريخ المتابعات).
- نموذج "زيارة طبية" لطاقم العيادة المخوّل فقط: الشكوى الرئيسية، الملاحظات السريرية،
  التشخيص، خطة العلاج، تعليمات المتابعة، الموعد القادم، المرفقات — تُدخل يدويًا من
  الطبيب/الطاقم الطبي فقط، دون أي توليد تلقائي لمعلومات أو تشخيصات طبية.
- تشفير وحماية مناسبة للبيانات الحساسة، مع التزام صارم بمبدأ "أقل صلاحية ممكنة" لكل دور.

## المرحلة 6 — نظام المتابعة والتذكيرات

- صفحة متابعة مخصصة: متابعات اليوم، هذا الأسبوع، القادمة، والمتأخرة، مع إمكانية تحويلها
  إلى موعد وتحديدها كمكتملة.
- بنية تذكيرات قابلة للتوسعة (تأكيد الموعد، تذكير بالغد، تذكير باليوم، متابعة مستحقة،
  موعد فائت) مع نقاط تكامل جاهزة لخدمات واتساب/SMS/بريد إلكتروني — تُفعَّل فقط عند توفر
  بيانات الاعتماد (API credentials) الحقيقية لهذه الخدمات، دون أي تكامل وهمي أو مزيف.

## ملاحظات تنفيذية

- كل مرحلة تُبنى وتُختبر بشكل مستقل قبل الانتقال للتالية.
- الأولوية دائمًا لأمان بيانات المريضات: مصادقة قوية، صلاحيات دقيقة، وتسجيل كامل لأي
  وصول أو تعديل على السجلات الطبية.
